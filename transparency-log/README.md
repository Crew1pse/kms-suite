# transparency-log

Журнал прозрачности (по RFC 9162 / Certificate Transparency) как неизменяемый аудит для `threshold-kms`.

## Идея
Журнал публично читаем и **не обязан быть честным**: честность проверяют мониторы.
- Каждая запись — лист дерева Меркла (доменное разделение `0x00` лист / `0x01` узел).
- Сервер подписывает корень (STH: размер, корень, время; Ed25519 с доменным префиксом).
- **Доказательство включения**: запись N есть в дереве с корнем R (O(log n) хэшей).
- **Доказательство согласованности**: дерево размера n — продолжение дерева размера m (история не переписана).
- **Монитор** хранит последний проверенный STH и при обновлении ловит: недействительную подпись, откат (размер
  уменьшился), форк (тот же размер, другой корень), переписанную историю, подмену содержимого записи.

## Файлы
| Файл | Роль |
|---|---|
| `src/merkle.py` | дерево, доказательства, верификаторы; проверено эталонными корнями CT и независимой реализацией |
| `src/tlog.py` | append-only SQLite (триггеры), STH, самопроверка при старте |
| `src/server.py` | HTTP API: `POST /v1/entries` (Bearer), `GET /v1/sth`, `/v1/entries/{i}`, `/v1/proof/inclusion`, `/v1/proof/consistency` |
| `src/monitor.py` | независимый наблюдатель |
| `demo.py` | сквозной сценарий и обнаружение подмены |

Запуск сервера: `TLOG_APPEND_TOKEN=... python src/server.py` (переменные `TLOG_DB`, `TLOG_KEY`, `TLOG_HOST`, `TLOG_PORT`).
Тесты: `cd tests && pip install -r requirements-test.txt && pytest` (174 теста).

## Подключение к KMS
Узел `threshold-kms` пишет событие (`store` / `retrieve` / `shred`) **до** выполнения операции. Если журнал
недоступен — операция отклоняется (503), состояние не меняется (fail-closed). В журнал попадает только
`SHA-256(key_id)`, без имён ключей и без долей. Включение: `AUDIT_LOG_URL`, `AUDIT_LOG_TOKEN`, `AUDIT_LOG_CA`.

## Что это НЕ даёт (честные ограничения)
- **Split-view**: если оператор показывает разным мониторам разные деревья, одиночный монитор этого не увидит.
  Нужен gossip между мониторами или независимые свидетели (witness cosigning).
- Подписанному STH верят, пока ключ подписи не скомпрометирован; нужны хранение ключа в HSM и ротация.
- Триггеры SQLite не защищают от человека с доступом к файлу; гарантию дают мониторы и самопроверка при старте.
- Одиночный узел, дерево целиком в памяти (O(n) на старте); для больших журналов нужны компактные «фронтиры»
  и шардирование.
- Время в STH не заверено внешним источником (нет TSA).
- Запись по Bearer-токену; в проде — mTLS и отдельные права на запись.
- Журнал не скрывает факт операции — он делает его необратимо **видимым**.
