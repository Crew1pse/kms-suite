# threshold-signing: DKG + FROST (Ed25519)

Пороговая подпись **t из n без доверенного дилера**: приватный ключ не существует целиком ни в одном месте,
а результат - обычная подпись Ed25519 (RFC 8032), которую проверяет любой стандартный верификатор.

## Файлы
| Файл | Роль |
|---|---|
| `src/ed25519_group.py` | группа Ed25519 на libsodium (PyNaCl): строгая валидация точек и скаляров, Лагранж |
| `src/frost.py` | FROST(Ed25519, SHA-512) по структуре RFC 9591: коммитменты, коэффициенты связывания, доли подписи, агрегация с выявлением виновного |
| `src/dkg.py` | DKG Педерсена с доказательствами владения (FROST paper, Fig. 1): 2 раунда, Feldman-проверка долей |
| `demo.py` | сквозной сценарий (7 шагов), включая подпись STH журнала прозрачности пороговым ключом |
| `tests/` | 53 теста: см. ниже |

## Что проверено
- Подписи каждого кворума (1..n из n, несколько пар t/n) принимает **независимый** `Ed25519PublicKey.verify` из `cryptography`.
- `base_mul` совпадает с публичным ключом, который выводит `cryptography` из seed (RFC 8032).
- Атаки: чужой/повторный nonce, подмена своего коммитмента координатором, дубликаты и мусорные идентификаторы,
  нейтральные и малого порядка точки, разные сообщения у разных подписантов, неверная доля (называется виновный),
  rogue-key в DKG, копирование чужого PoK под своим номером, перенос PoK между сессиями, подмена доли, мусорные пакеты.
- Мутационная проверка: 22 намеренные поломки кода, все пойманы, кроме одной эквивалентной (верификатор строже RFC на R=нейтральный).
- Интеграция: `transparency-log` подписывает STH пороговым ключом; монитор проверяет его штатно.

## Честные ограничения (читать обязательно)
- **Не аудировано. Не для настоящих секретов.** Учебная реализация; побайтовая совместимость с другими
  FROST-библиотеками **не проверена** (векторы из RFC 9591 не прогонялись): структуры и хэши следуют RFC по памяти, а
  корректность подтверждена независимым Ed25519-верификатором, но не эталонными векторами.
- DKG Педерсена допускает смещение распределения ключа активным злоумышленником (Gennaro et al.); для безопасности
  FROST это не критично, но ключ не строго равномерный. Нет устойчивости (robustness): один злоумышленник может прервать DKG.
  Виновный называется, процедуру нужно перезапустить без него.
- Нет сетевого слоя: доли DKG (`Round2Package`) обязаны идти по аутентифицированному и шифрованному каналу (mTLS).
- Секреты в памяти Python (int) не стираются; арифметика скаляров на Python не в постоянном времени
  (умножения точек выполняет libsodium). Для боевого применения: HSM/TEE и проверенная библиотека.
- Nonce хранятся в памяти процесса: перезапуск между раундами теряет их (подпись просто нужно начать заново), а
  клонирование состояния процесса (снапшот ВМ) опасно: это та же ситуация, что и повторное использование nonce.
- Только Ed25519 (не secp256k1 и не P-256, которые использует остальной suite).
- Идентифицируемый отказ есть, а защиты от DoS со стороны координатора нет.
