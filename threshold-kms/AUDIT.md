# Аудит threshold-kms

Метод: property-based тесты (Hypothesis), дифференциальное сравнение с `cryptography`, фаззинг API,
мутационная проверка самих тестов. Запуск: `cd tests && pip install -r requirements-test.txt && pytest`.
Итог: 49 тестов проходят; 9 намеренных поломок кода ловятся.

## Находки
| # | Где | Проблема | Статус |
|---|---|---|---|
| 1 | `point_compressor.decompress` | Для x не на кривой бросался `AssertionError` из `ecdsa`, а не `ValueError`; при `python -O` assert вырезается, и функция вернула бы точку вне кривой (invalid-curve) | Исправлено явной проверкой `y*y == x^3+7` |
| 2 | `point_compressor.decompress` | Принимались x ≥ p (x и x+p давали одну точку: неканоническая кодировка, malleability) | Исправлено |
| 3 | тесты | Мутационная проверка показала 2 пропущенных случая: доля (0, secret) и валидные коммитменты неверной длины | Тесты добавлены, мутанты ловятся |

Не найдено: 5xx на фаззинге API (случайные JSON, любые key_id, огромные и битые тела), расхождений с `cryptography`
в сжатии точек и выводе публичного ключа, ошибок в GF(2^8) и Shamir над кольцом по модулю q.

## Что аудит НЕ покрывает
- Тайминговые и прочие побочные каналы: чистый Python `ecdsa` делает скалярное умножение на секретах не в постоянном
  времени. Нужен отдельный анализ (dudect-подобный) или переход на проверенную библиотеку.
- TLS/mTLS на уровне сети (рукопожатия, версии, шифры), нагрузочные и DoS-тесты.
- Хранение: остаточные данные в файлах SQLite/WAL/снапшотах после shred.
- Формальная верификация протокола; независимое ревью криптографом.
