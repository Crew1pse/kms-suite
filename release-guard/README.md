# release-guard

Защита цепочки поставок: артефакт нельзя подменить незаметно.

| Слой | Что делает |
|---|---|
| Детерминированный tar.gz | одно и то же дерево -> побайтно тот же архив (без mtime/uid, отсортированный порядок, gzip mtime=0) |
| CycloneDX SBOM | только зафиксированные `==` зависимости; без времени и случайных UUID, тоже воспроизводим |
| in-toto Statement + SLSA provenance | субъект = SHA-256 артефакта, хэш SBOM, builder, хэш исходников |
| DSSE | подпись над PAE (проверен на официальном векторе); порог из N **разных** доверенных ключей |
| Журнал прозрачности | запись (артефакт, конверт) + доказательство включения + подписанный STH из `../transparency-log` |
| Политика | доверенные ключи/порог, разрешённые builders, запрещённые компоненты, защита от отката журнала, пересборка |

Подписантом может быть и **пороговый FROST** из `../threshold-signing`: подпись обычная Ed25519, проверяющему не важно,
что за ней 3 из 5 (тест есть). Запуск: `pytest && python demo.py`.

Проверено 53 тестами и мутационно (33 поломки кода, не пойманы только эквивалентные).

## Честные ограничения
- Это инструмент проверки, а не CI-система: **builder доверенный по заявлению**, hermetic-сборки и изоляции нет.
  Реальная SLSA-гарантия требует сборки на изолированной платформе, которая подписывает provenance сама.
- Воспроизводимость доказана только для tar.gz из исходников; сборка wheel/образов/бинарников зависит от тулчейна.
- SBOM строится из `requirements.txt`, а не из реально установленного дерева; транзитивные зависимости не видны,
  если они не зафиксированы. Нет сверки с базой уязвимостей (blocklist задаётся вручную).
- Журнал защищает от тихой подмены только при наличии независимых мониторов (split-view описан в `transparency-log`).
- Не аудировано; формат bundle свой, не sigstore/cosign-совместимый.

## Постквантовые подписи (ML-DSA-65, FIPS 204)
DSSE принимает ключи `ml-dsa-65` (нативно из `cryptography` 50). Политика `require_algs=("ed25519","ml-dsa-65")` требует
**гибрид**: релиз принят, только если есть валидные подписи обоих алгоритмов. Сломали один (Ed25519 квантовым компьютером
или ML-DSA найденной слабостью) - подделать релиз всё равно нельзя (тест «сломали Ed25519»).
Цена: подпись 3309 байт против 64, открытый ключ 1952 против 32.
Мутации ML-DSA-пути: 5 из 5 убиты (всего в проекте 25 из 25 за два прогона).

Что НЕ переведено на PQ: подписи STH журнала прозрачности (Ed25519), FROST (Ed25519, пороговой ML-DSA нет в стандарте),
ECDSA в `workload-identity`. Переход всей цепочки - отдельная работа; здесь сделан артефакт-уровень.

## Воспроизводимый wheel
`src/wheel.py` собирает настоящий wheel (PEP 427) побайтно детерминированно: фиксированные даты ZIP, сортировка, RECORD с хэшами,
чистый Python (`py3-none-any`). Тесты: одинаковый результат при смене mtime и каталога, `pip install` реально ставит пакет и он
работает, подмена файла и лишний файл ловятся проверкой RECORD, пересборка из исходников сверяется с подписанным хэшем
(`build_release(..., kind="wheel")`). Выжившие при мутациях два варианта эквивалентны (ZIP хранит секунды с шагом 2; порядок записей
остаётся детерминированным). Ограничение: только pure-Python; бинарные wheel и образы зависят от тулчейна и здесь не покрыты.
